RustAPI gives you FastAPI's decorator ergonomics — routes, pydantic validation, OpenAPI, and a built-in MCP server — on top of a tokio/hyper engine written in Rust. It's honest about the one thing that doesn't change: the Python you write still runs in CPython.

Getting started

Install

Not yet on PyPI under this name — build from source with maturin until it is:

# clone, then from the repo root
pip install maturin
maturin develop --release

# if you get a PyO3 ABI3 error, try this instead:
PYO3_USE_ABI3_FORWARD_COMPATIBILITY=1 maturin develop --release

# once published:
pip install rustapi-framework
Getting started

Quickstart

One Engine instance serves REST routes and MCP tools together.

from rustapi import Engine
from pydantic import BaseModel

app = Engine()

class Item(BaseModel):
    name: str
    price: float

@app.get("/")
def root():
    return {"message": "hello"}

@app.post("/items")
def create_item(item: Item):
    return {"created": item.name, "price": item.price}

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=8000)

Then GET /docs for Swagger UI, GET /openapi.json for the schema.

Core

Routing & validation

Every standard verb is supported:

DecoratorNotes
@app.get(path)—
@app.post(path)Body arg typed as a pydantic model is validated automatically
@app.put(path) / @app.patch(path)Same body handling as POST
@app.delete(path)—
@app.options(path) / @app.head(path)Register manually, or use enable_cors() for automatic OPTIONS

Path params (/items/{id}) and query params arrive as plain strings on a req object — there's no id: int-style automatic coercion yet (see roadmap).

Not yet accurate to claim

A raised or invalid-body exception currently returns a generic HTTP 500 — there's no HTTPException and no automatic 422 on a failed pydantic validation yet. Don't design an app around status-code-based error handling until this lands.

Core

MCP server

The same Engine exposes an MCP server over JSON-RPC 2.0 at POST /mcp (Streamable HTTP transport — no stdio, no SSE push yet).

@app.tool()
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

@app.resource("config://app-name")
def app_name() -> str:
    return "my-app"

@app.prompt()
def greeting(name: str) -> str:
    return f"Say hello to {name} warmly."

Input schemas are generated automatically from type hints — no separate schema to hand-write.

Core

CORS

Native, not middleware — handles preflight automatically:

app.enable_cors(
    origins=["https://yourfrontend.com"],
    allow_credentials=True,
)

Omit origins to allow any origin (*). The matching request Origin is echoed back per spec — it's not a static comma-joined header.

Running it

Deployment

workers=N

Spawns N processes sharing one listening socket via SO_REUSEPORT. Each is a full Rust worker with its own Python interpreter.

reload=True

Watches for .py changes and restarts workers. Development only.

app.run(host="0.0.0.0", port=8000, workers=4)
Can't do this yet

There's no ASGI callable anymore, so this can't be run under uvicorn/gunicorn, and nothing from the Sentry/Prometheus/OpenTelemetry ASGI-middleware ecosystem attaches. .run() is the only way in.

Performance, honestly

Business logic does not run at Rust speed. Whatever you write inside a handler body executes through CPython — same interpreter, same per-instruction cost, whether it's under RustAPI or Flask or FastAPI.

There is no ORM story. Nothing here accelerates a database call. If you use SQLAlchemy, asyncpg, or anything else inside a handler, it runs at its own normal speed — the framework doesn't touch it.

What genuinely is fast: everything in the diagram above marked rust — the transport, the router, the validation handoff, JSON encode/decode, the MCP JSON-RPC layer. That's a real, measurable win over a pure-Python stack doing the same work.

The one real escape hatch

A handler can call a genuine #[pyfunction] compiled into the extension (see compute() in the source) — that piece runs at native speed, GIL released. But that's you writing Rust for that one hot path, not the framework accelerating arbitrary Python.
